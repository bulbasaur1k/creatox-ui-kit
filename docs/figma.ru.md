# Кит в Figma

Источник правды — код. Компоненты снимаются с живого листа `demo/sheet.html`, токены берутся из `@theme`. После релиза кита шаги повторяются, и макет догоняет код, а не наоборот.

Путей в Figma два, и выбирает их приложение:

- **Веб-Figma** — SVG. Плагины разработчика веб-версия не запускает, а SVG открывает любая: файл перетаскивается на холст. Раздел «Без десктопа» ниже.
- **Десктопная Figma** — плагин из `figma/`: переменные с режимами Light и Dark, текстовые стили, страница с auto layout. Разделы 1 и 2.

## Без десктопа: лист как SVG

1. Открыть лист — на Pages или локально после `npm run dev`:
   - https://bulbasaur1k.github.io/creatox-ui-kit/demo/sheet.html
   - http://localhost:5180/sheet.html (и `?theme=dark` для тёмной темы)
2. Нажать «SVG для Figma» в шапке. Скачается `creatox-ui-kit.light.svg` или `creatox-ui-kit.dark.svg`.
3. В веб-Figma перетащить файл на холст (или **Main menu → File → Place image…**, выбрать файл). Лист встанет одним фреймом.

Внутри — группа на каждую секцию листа (`Typography`, `Button`, `Fields`, `Layers`, `Layout`, `SideNav`, …) и группы по компонентам. Фон и рамки — прямоугольники, текст — редактируемые текстовые слои в Inter и Roboto Mono, иконки — векторы, тени — эффект Drop shadow. Чего SVG не несёт: auto layout (раскладка — абсолютными координатами), переменных и текстовых стилей (цвета — обычные заливки). Из группы делается компонент так же, как из фрейма: выделить → **Create component**.

Переносы строк стоят там, где их поставил браузер, а шрифт в Figma другой — длинная строка может разойтись с оригиналом на пару пикселей.

## Плагин

Папка `figma/` — плагин разработчика, без публикации, работает только в десктопном приложении:

1. Figma → меню → **Plugins → Development → Import plugin from manifest…** → выбрать `figma/manifest.json`.
2. Открыть файл библиотеки, запустить **creatox-ui-kit**. У него две вкладки — «Токены» и «Лист».

## 1. Токены → переменные

`figma/tokens.figma.json` лежит в репозитории и пересобирается командой

```bash
npm run figma:tokens
```

Это 93 токена из `@theme` с двумя значениями каждый — light и dark. Цвета уже переведены из oklch в то, что понимает Figma.

Вкладка «Токены»: выбрать `figma/tokens.figma.json` (или вставить его содержимое), нажать «Импортировать». Получится коллекция переменных **creatox-ui-kit** с режимами **Light** и **Dark**:

| Токен в CSS               | Переменная           | Тип                   |
| ------------------------- | -------------------- | --------------------- |
| `--color-accent-hover`    | `color/accent-hover` | Color, два режима     |
| `--spacing-control-md`    | `spacing/control-md` | Number, px (rem × 16) |
| `--radius-control`        | `radius/control`     | Number                |
| `--text-ui`               | `text/ui`            | Number                |
| `--duration-snap`         | `duration/snap`      | Number, мс            |
| `--font-sans`, `--ease-*` | `font/…`, `ease/…`   | String                |

И текстовые стили `text/micro … text/display` — размер, интерлиньяж, трекинг из тех же токенов. Шрифт — первый из стека кита, который найдётся в Figma; для системного стека это будет Inter, если он установлен, — подмените вручную на тот, что используете в макетах.

Повторный импорт **обновляет** значения существующих переменных по имени, ничего не дублирует и не рвёт привязки в макетах. Переменная, которую в коде переименовали, останется в Figma старой — удалить её надо руками.

## 2. Компоненты → страница

Лист `demo/sheet.html` — каждый компонент во всех состояниях, размерах и тонах, подписанный, секциями. На Pages он живёт по адресам

- светлая тема: https://bulbasaur1k.github.io/creatox-ui-kit/demo/sheet.html
- тёмная: https://bulbasaur1k.github.io/creatox-ui-kit/demo/sheet.html?theme=dark

Вкладка «Лист»: адрес листа уже подставлен, отметить Light и/или Dark, нажать «Импортировать лист». Плагин открывает лист у себя в окне, уменьшенный, и просит у него снимок — лист отвечает деревом того, что нарисовал браузер: боксы с заливками, обводками, тенями и скруглениями, текст с его шрифтом, иконки как SVG (`demo/snapshot.ts`). По снимку плагин рисует на странице **creatox-ui-kit** секцию **Light** или **Dark**, а в ней — фрейм на каждую секцию листа: `Typography`, `Button`, `Fields`, `Choice`, … Внутри фреймы названы по компонентам (`button`, `field`, `choice-control`) и по подписям строк листа.

Что становится чем:

| В браузере                                         | В Figma                                     |
| -------------------------------------------------- | ------------------------------------------- |
| Элемент с фоном, рамкой, тенью                     | Frame с fill, stroke (внутрь), effect       |
| `display: flex` без переносов и с ними             | Auto layout с теми же gap и padding         |
| Grid, абсолютное позиционирование                  | Frame с абсолютными координатами            |
| Текстовый узел                                     | Text: размер, начертание, интерлиньяж, цвет |
| `<svg>`                                            | Векторная группа, `currentColor` подставлен |
| Галочка, точка радио, стрелка дерева (`clip-path`) | Вектор-полигон                              |
| Ползунок тумблера, значение прогресса, ручка range | Frame на своём месте                        |
| Тултип, непоставленная галочка, `display: none`    | Ничего                                      |

Каждый auto layout после сборки сверяется с браузером: если Figma разложила детей не туда (обычно из-за `margin`, которого у auto layout нет), контейнер откатывается к абсолютным координатам — в логе плагина это «откатов к абсолютным N». Повторный импорт перерисовывает секцию темы целиком, остальное на странице не трогает; свои компоненты, вырезанные из прошлого импорта, держите вне секций Light и Dark.

Что приближено, а не снято:

- Шрифт. Лист рисуется системным шрифтом, которого в Figma нет; плагин берёт первый из стека кита, который у Figma есть, иначе Inter, для моноширинного — JetBrains Mono или Roboto Mono. Однострочный текст ставится с авто-шириной, чтобы не переноситься, если шрифт Figma чуть шире, — соседи в auto layout от этого сдвигаются на пиксель-другой.
- Анимации не снимаются: спиннер в кнопке и бегущая полоса неопределённого `Progress` придут пустыми.
- Слои — открытые списки `Select`/`Combobox`/`TreeSelect`, календарь `DatePicker`, меню, `Popover`, `Dialog`, `Sheet`, тосты — в секции `Layers` стоят раскрытыми прямо в потоке листа (`demo/sheet.css`): те же классы и та же отрисовка, но без привязки к окну и без анимации. Поверх страницы, как в продукте, их в Figma надо поставить руками.

Дальше — дизайнерская работа: выделить вариант → **Create component**, варианты одной кнопки → **Combine as variants**, заливки привязать к переменным из шага 1 (выделение → цвет → «Apply variable», или плагином, который сопоставляет заливки переменным по значению, — Tokens Studio умеет).

### Если лист не открывается внутри плагина

Плагин ходит только на `bulbasaur1k.github.io` (и на `localhost:5180` у разработчика — это `networkAccess` в манифесте). Если сеть закрыта или лист нужен с другой машины, снимок можно передать файлом: открыть лист в браузере, нажать «Снимок для плагина» в шапке — скачается `sheet.light.figma.json` (для `?theme=dark` — `sheet.dark.figma.json`), — и на вкладке «Лист» выбрать его в «Из файла». Локальный лист: `npm run dev` и адрес `http://localhost:5180/sheet.html` в поле вместо Pages.

Тот же лист по-прежнему берёт и [html.to.design](https://www.figma.com/community/plugin/1159123024924461424), если нужен именно он: вкладка **URL**, адрес листа, ширина 1440.

## 3. Как держать в синхроне

- Релиз кита → `npm run figma:tokens` → импорт плагином → переменные обновлены. Макеты, привязанные к переменным, перекрасятся сами.
- Новый компонент или состояние → он появляется на листе `demo/sheet.tsx` (это часть работы над компонентом, как стори) → после выкладки на Pages дизайнер жмёт «Импортировать лист» ещё раз.
- Спорные пиксели решаются в коде: лист — то, что реально рендерит браузер, и снимок берётся с него же.

## Чего здесь нет

Компонентов Figma. Плагин рисует фреймы, а не компоненты и варианты: какие из шести кнопок одной строки — варианты одного компонента, а какие — состояния другого, решает дизайнер, и это решение живёт в библиотеке, а не в коде. Плагин ничего не знает о ките: он повторяет то, что нарисовал браузер, и потому не расходится с ним.
